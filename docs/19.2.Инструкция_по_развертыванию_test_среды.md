## 1. Подготовка сервера и дисковой подсистемы

### 1.1. Настройка RAID

**Цель:** Создать два RAID 1 массива из 4 дисков по 2TB каждый.

**Вход в RAID контроллер (HP Smart Array P410) - F8:**
- Собрать два RAID массива:
  - RAID 10 из дисков 0 и 1
  - RAID 10 из дисков 2 и 3
- В Boot Volume выбрать **Direct Attached Storage**
- Выбрать в качестве загрузочного первый логический диск


**Создание RAID 1 массивов (через hpssacli после установки ОС):**
```bash
# Установка утилиты (если недоступна в репозитории)
sudo apt update
sudo apt install -y hpssacli

# Просмотр дисков
sudo hpssacli ctrl all show config

# Создание RAID 1 (пример для контроллера, замените на ваш)
sudo hpssacli ctrl slot=0 create type=ld drives=1I:1,1I:2 raid=1
sudo hpssacli ctrl slot=0 create type=ld drives=1I:3,1I:4 raid=1

# Проверка результата
sudo hpssacli ctrl slot=0 ld all show
```

**Итоговая конфигурация:**
- `/dev/sda` и `/dev/sdb` — первый RAID 1 массив (2TB полезного пространства)
- `/dev/sdc` и `/dev/sdd` — второй RAID 1 массив (2TB полезного пространства)

### 1.2 Установка параметров USB

**Вход в BIOS - F10:**
- Установить USB‑настройки
  - USB Functions	- Enabled
  - Legacy USB Support - Enabled
  - USB 2.0 Controller - Enabled
  - USB 2.0 Controller Mode - HiSpeed
  - BIOS EHCI Hand-Off - Enabled
  - Hot Plug USB FDD Support - Disabled
  - USB Mass Storage Device Configuration → Emulation Type - Hard Drive

### 1.3 Подготовка загрузочного диска

- Скачать образ ОС
- Проверить хэш образа
- На Windows (Rufus) установить
  - Схема раздела: MBR (для BIOS) или GPT (для UEFI)
  - Целевая система: BIOS или UEFI (без CSM)
  - Режим записи: ISO Image (не DD!)
  - Проверить на плохие блоки
- Установить на флешку (желательно USB2, размер не более 32GB)


### 1.4. Установка Ubuntu 24.04 LTS

**Использована автоматическа разметка загрузочного диска при установке:**

| Диск | Раздел | Точка монтирования | Размер | Файловая система |
|------|--------|-------------------|--------|------------------|
| /dev/sda | /dev/sda1 | / | 2TB    | ext4 |
| /dev/sdb | | Используется как зеркало /dev/sda (RAID 1) |        | |
| /dev/sdc | /dev/sdc1 | /mnt/data | 2TB    | ext4 |
| /dev/sdd | | Используется как зеркало /dev/sdc (RAID 1) |        | |

**Вручную:**

| Диск | Раздел | Точка монтирования | Размер | Файловая система |
|------|--------|-------------------|--------|------------------|
| /dev/sda | /dev/sda1 | /boot | 1GB | ext4 |
| | /dev/sda2 | / | 100GB | ext4 |
| | /dev/sda3 | swap | **НЕ ИСПОЛЬЗОВАТЬ (swap отключен для K8s)** | - |
| | /dev/sda4 | /var/lib/docker | остаток | ext4 |
| /dev/sdb | | Используется как зеркало /dev/sda (RAID 1) | | |
| /dev/sdc | /dev/sdc1 | /mnt/data | 2TB | ext4 |
| /dev/sdd | | Используется как зеркало /dev/sdc (RAID 1) | | |

**Важно:** При установке Ubuntu **НЕ создавайте swap раздел**. Kubernetes требует отключенного swap.

**После установки ОС:**

```bash
# Обновление системы
sudo apt update && sudo apt upgrade -y

# Установка необходимых пакетов
sudo apt install -y \
    curl wget git vim htop \
    apt-transport-https ca-certificates gnupg lsb-release \
    jq yq net-tools bridge-utils \
    nfs-common cifs-utils

# Отключение swap (дополнительная проверка)
sudo swapoff -a
# Удаление swap из /etc/fstab
sudo sed -i '/swap/d' /etc/fstab

# Настройка параметров ядра для HDD (без swap)
cat << EOF | sudo tee /etc/sysctl.d/99-k8s.conf
vm.swappiness=0
vm.vfs_cache_pressure=50
net.ipv4.ip_forward=1
net.bridge.bridge-nf-call-iptables=1
fs.inotify.max_user_watches=524288
fs.inotify.max_user_instances=512
EOF

sudo sysctl --system

# Настройка монтирования /mnt/data
sudo mkdir -p /mnt/data
sudo mount /dev/sdc1 /mnt/data

# Добавление в fstab для автоматического монтирования
echo "/dev/sdc1 /mnt/data ext4 defaults,noatime 0 2" | sudo tee -a /etc/fstab

# Создание директорий для хранения данных
sudo mkdir -p /mnt/data/k8s-storage/{postgres,elasticsearch,kafka,minio,chroma,harbor,monitoring}
sudo chmod 755 /mnt/data/k8s-storage
```

## 2. Установка базового ПО

### 2.1. Установка Docker

```bash
# Удаление старых версий
sudo apt remove -y docker docker-engine docker.io containerd runc

# Установка через официальный репозиторий
sudo mkdir -p /etc/apt/keyrings
curl -fsSL https://download.docker.com/linux/ubuntu/gpg | sudo gpg --dearmor -o /etc/apt/keyrings/docker.gpg

echo "deb [arch=$(dpkg --print-architecture) signed-by=/etc/apt/keyrings/docker.gpg] https://download.docker.com/linux/ubuntu $(lsb_release -cs) stable" | sudo tee /etc/apt/sources.list.d/docker.list

sudo apt update
sudo apt install -y docker-ce docker-ce-cli containerd.io docker-buildx-plugin docker-compose-plugin

# Настройка Docker для kind (использование systemd cgroup)
sudo mkdir -p /etc/docker
sudo cat << 'EOF' | sudo tee /etc/docker/daemon.json
{
  "exec-opts": ["native.cgroupdriver=systemd"],
  "log-driver": "json-file",
  "log-opts": {
    "max-size": "100m",
    "max-file": "3"
  },
  "storage-driver": "overlay2",
  "data-root": "/var/lib/docker"
}
EOF

# Перезапуск Docker
sudo systemctl restart docker
sudo systemctl enable docker

# Добавление текущего пользователя в группу docker
sudo usermod -aG docker $USER
newgrp docker
```

```bash
apiVersion: networking.istio.io/v1beta1
kind: DestinationRule
metadata:
  name: rag-circuit-breaker
  namespace: rag
spec:
  host: "*.rag.svc.cluster.local"
  trafficPolicy:
    connectionPool:
      tcp:
        maxConnections: 10
      http:
        http1MaxPendingRequests: 5
        http2MaxRequests: 100
        maxRequestsPerConnection: 10
    outlierDetection:
      consecutive5xxErrors: 5
      interval: 30s
      baseEjectionTime: 30s
      maxEjectionPercent: 50
EOF
```

### 5.3. Установка OpenTelemetry Collector

```bash
      timeout: 1s
      send_batch_size: 1024
    memory_limiter:
      check_interval: 1s
      limit_mib: 512
    probabilistic_sampler:
      sampling_percentage: 10.0
    tail_sampling:
      policies:
        - name: errors-policy
          type: status_code
          status_code:
            status_codes: [ERROR]
        - name: slow-policy
          type: latency
          latency:
            threshold_ms: 500
        - name: probabilistic-policy
          type: probabilistic
          probabilistic:
            sampling_percentage: 10
      decision_wait: 10s
      num_traces: 10000
      expected_new_traces_per_sec: 100
  exporters:
    otlp/jaeger:
      endpoint: jaeger.monitoring.svc.cluster.local:4317
      tls:
        insecure: true
    logging:
      loglevel: debug
      sampling_initial: 5
      sampling_thereafter: 200
  service:
    pipelines:
      traces:
        receivers: [otlp]
        processors: [memory_limiter, tail_sampling, batch]
        exporters: [otlp/jaeger, logging]
resources:
  requests:
```

### 9.3. GitHub Actions workflow с DevSecOps этапами

```yaml
# .github/workflows/devsecops-ci-cd.yml
cat << 'EOF' > devsecops-ci-cd.yml
name: DevSecOps CI/CD Pipeline

on:
  push:
    branches: [main, develop]
  pull_request:
    branches: [main]
  schedule:
    - cron: '0 0 * * 0'  # Еженедельное сканирование

env:
  REGISTRY: harbor.rag.local
  NAMESPACE: rag

jobs:
  # ==================== JOB 1: SAST (Static Application Security Testing) ====================
  sast:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      
      - name: Run Semgrep (SAST)
        uses: returntocorp/semgrep-action@v1
        with:
          config: |
            p/python
            p/secrets
            p/owasp-top-ten
            p/security-audit
      
      - name: Upload Semgrep results
        uses: github/codeql-action/upload-sarif@v3
        with:
          sarif_file: semgrep.sarif

  # ==================== JOB 2: Secret Scanning ====================
  secret-scan:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
        with:
          fetch-depth: 0
      
      - name: Run gitleaks (Secret Detection)
        uses: gitleaks/gitleaks-action@v2
        env:
          GITHUB_TOKEN: ${{ secrets.GITHUB_TOKEN }}
      
      - name: Upload gitleaks results
        if: failure()
        uses: actions/upload-artifact@v4
        with:
          name: gitleaks-report
          path: gitleaks-report.json

  # ==================== JOB 3: SCA (Software Composition Analysis) ====================
  sca:
    runs-on: ubuntu-latest
    needs: [sast, secret-scan]
    steps:
      - uses: actions/checkout@v4
      
      - name: Run Trivy for dependencies (SCA)
        uses: aquasecurity/trivy-action@master
        with:
          scan-type: 'fs'
          scan-ref: '.'
          format: 'sarif'
          output: 'trivy-deps.sarif'
          severity: 'CRITICAL,HIGH'
      
      - name: Upload Trivy SCA results
        uses: github/codeql-action/upload-sarif@v3
        with:
          sarif_file: trivy-deps.sarif

  # ==================== JOB 4: Build & Container SCA ====================
  build:
    runs-on: ubuntu-latest
    needs: [sca]
    steps:
      - uses: actions/checkout@v4
      
      - name: Set up Docker Buildx
        uses: docker/setup-buildx-action@v3
      
      - name: Login to Harbor
        uses: docker/login-action@v3
        with:
          registry: ${{ env.REGISTRY }}
          username: ${{ secrets.HARBOR_USERNAME }}
          password: ${{ secrets.HARBOR_PASSWORD }}
      
      - name: Build and push with Trivy scan
        uses: docker/build-push-action@v5
        with:
          context: .
          file: Dockerfile
          push: true
          tags: |
            ${{ env.REGISTRY }}/${{ github.event.repository.name }}:${{ github.sha }}
            ${{ env.REGISTRY }}/${{ github.event.repository.name }}:latest
      
      - name: Run Trivy on container image (Container SCA)
        uses: aquasecurity/trivy-action@master
        with:
          image-ref: ${{ env.REGISTRY }}/${{ github.event.repository.name }}:${{ github.sha }}
          format: 'sarif'
          output: 'trivy-image.sarif'
          severity: 'CRITICAL,HIGH'
      
      - name: Upload Trivy image results
        uses: github/codeql-action/upload-sarif@v3
        with:
          sarif_file: trivy-image.sarif

  # ==================== JOB 5: Deploy to Test ====================
  deploy-test:
    runs-on: ubuntu-latest
    needs: [build]
    if: github.ref == 'refs/heads/main'
    steps:
      - uses: actions/checkout@v4
      
      - name: Install kubectl
        uses: azure/setup-kubectl@v4
      
      - name: Set up kubeconfig
        run: |
          mkdir -p $HOME/.kube
          echo "${{ secrets.KUBECONFIG_TEST }}" | base64 --decode > $HOME/.kube/config
      
      - name: Deploy with Helm
        run: |
          helm upgrade --install ${{ github.event.repository.name }} \
            ./helm/${{ github.event.repository.name }} \
            --namespace ${{ env.NAMESPACE }} \
            --set image.repository=${{ env.REGISTRY }}/${{ github.event.repository.name }} \
            --set image.tag=${{ github.sha }} \
            --wait

  # ==================== JOB 6: DAST (Dynamic Application Security Testing) ====================
  dast:
    runs-on: ubuntu-latest
    needs: [deploy-test]
    if: github.ref == 'refs/heads/main'
    steps:
      - uses: actions/checkout@v4
      
      - name: Run OWASP ZAP (DAST)
        uses: zaproxy/action-full-scan@v0.9.0
        with:
          target: 'http://api.rag.local'
          rules_file_name: '.zap/rules.tsv'
          cmd_options: '-a -t 60 -j -m 2'
          allow_issue_writing: true
          issue_title: 'ZAP DAST Report - ${{ github.event.repository.name }}'
      
      - name: Upload ZAP report
        uses: actions/upload-artifact@v4
        with:
          name: zap-report
          path: /home/runner/work/_actions/zaproxy/action-full-scan/v0.9.0/report.html

  # ==================== JOB 7: Quality Gate ====================
  quality-gate:
    runs-on: ubuntu-latest
    needs: [sast, secret-scan, sca, dast]
    if: always()
    steps:
      - name: Check for security failures
        run: |
          echo "Security scan results:"
          echo "SAST: ${{ needs.sast.result }}"
          echo "Secret Scan: ${{ needs.secret-scan.result }}"
          echo "SCA: ${{ needs.sca.result }}"
          echo "DAST: ${{ needs.dast.result }}"
          
          if [[ "${{ needs.sast.result }}" == "failure" || 
                "${{ needs.secret-scan.result }}" == "failure" ||
                "${{ needs.sca.result }}" == "failure" ||
                "${{ needs.dast.result }}" == "failure" ]]; then
            echo "Security checks failed! Promotion to production blocked."
            exit 1
          fi
EOF
```

```python
from opentelemetry import trace
from opentelemetry.instrumentation.flask import FlaskInstrumentor
from opentelemetry.instrumentation.requests import RequestsInstrumentor
from opentelemetry.instrumentation.sqlalchemy import SQLAlchemyInstrumentor

def init_telemetry(app, db_engine):
    # Инструментация Flask
    FlaskInstrumentor().instrument_app(app)
    
    # Инструментация HTTP запросов
    RequestsInstrumentor().instrument()
    
    # Инструментация БД
    SQLAlchemyInstrumentor().instrument(engine=db_engine)
    
    # Получение tracer
    tracer = trace.get_tracer(__name__)
    return tracer
EOF
```

### 14.4. Критерии для принятия решения о переходе на SSD

| Метрика | Порог для HDD | Действие |
|---------|---------------|----------|
| **Elasticsearch search latency** | > 500ms p95 | Рассмотреть миграцию на SSD |
| **PostgreSQL query latency** | > 200ms p95 | Рассмотреть миграцию на SSD |
| **Kafka producer latency** | > 100ms p95 | Рассмотреть миграцию на SSD |
| **Disk I/O wait** | > 20% постоянно | Рассмотреть миграцию на SSD |
| **Pod eviction due to disk pressure** | Любое событие | Срочная миграция на SSD |
| **Индексация документации (>10k документов)** | > 30 минут | Рассмотреть миграцию на SSD |

## 15. Рекомендации по переходу на SSD (Фаза 2)

### 15.1. Подготовка SSD дисков

```bash
# 1. Замена дисков в RAID контроллере
# Выключите сервер, замените два диска в одном RAID 1 массиве на SSD
# Включите сервер, войдите в RAID контроллер (F8)
# Создайте новый RAID 1 массив из SSD дисков

# 2. Разметка SSD
sudo fdisk -l /dev/sde  # идентифицируйте новый SSD массив
sudo mkfs.ext4 /dev/sde1
sudo mkdir -p /mnt/ssd
sudo mount /dev/sde1 /mnt/ssd

# Добавление в fstab
echo "/dev/sde1 /mnt/ssd ext4 defaults,noatime 0 2" | sudo tee -a /etc/fstab
```

### 15.2. Миграция критичных PVC

```bash
# 1. Остановка приложений
kubectl scale deployment postgres-postgresql -n infra --replicas=0
kubectl scale deployment elasticsearch-master -n infra --replicas=0
kubectl scale deployment kafka -n infra --replicas=0

# 2. Бэкап данных
sudo rsync -av /mnt/data/k8s-storage/postgres/ /mnt/ssd/postgres-backup/
sudo rsync -av /mnt/data/k8s-storage/elasticsearch/ /mnt/ssd/elasticsearch-backup/
sudo rsync -av /mnt/data/k8s-storage/kafka/ /mnt/ssd/kafka-backup/

# 3. Копирование данных на SSD
sudo rsync -av /mnt/data/k8s-storage/postgres/ /mnt/ssd/postgres/
sudo rsync -av /mnt/data/k8s-storage/elasticsearch/ /mnt/ssd/elasticsearch/
sudo rsync -av /mnt/data/k8s-storage/kafka/ /mnt/ssd/kafka/

# 4. Обновление PV
cat << 'EOF' > update-pv.yaml
apiVersion: v1
kind: PersistentVolume
metadata:
  name: postgres-pv
spec:
  capacity:
    storage: 50Gi
  local:
    path: /mnt/ssd/postgres

apiVersion: v1
kind: PersistentVolume
metadata:
  name: elasticsearch-pv
spec:
  capacity:
    storage: 100Gi
  local:
    path: /mnt/ssd/elasticsearch
---
apiVersion: v1
kind: PersistentVolume
metadata:
  name: kafka-pv
spec:
  capacity:
    storage: 50Gi
  local:
    path: /mnt/ssd/kafka

kubectl apply -f update-pv.yaml

cat << 'EOF' | kubectl apply -f -

  name: local-ssd

# 6. Запуск приложений

kubectl scale deployment elasticsearch-master -n infra --replicas=1
```

## Приложение B: Скрипты для автоматизации

### B.1. Скрипт проверки готовности всех сервисов

```bash
#!/bin/bash
# check-all-services.sh

echo "Waiting for all services to be ready..."

while true; do
  READY_COUNT=$(kubectl get pods -A -o json | jq '[.items[] | select(.status.phase == "Running")] | length')
  TOTAL_COUNT=$(kubectl get pods -A -o json | jq '.items | length')
  
  echo "Ready: $READY_COUNT / $TOTAL_COUNT"
  
  if [ "$READY_COUNT" -eq "$TOTAL_COUNT" ]; then
    echo "All services are ready!"
    break
  fi
  
  sleep 5
done
```
