## 1. Подготовка сервера и дисковой подсистемы

### 1.1. Настройка RAID

**Цель:** Создать два RAID 1 массива из 4 дисков по 2TB каждый.

**Вход в RAID контроллер (HP Smart Array P410) - F8:**
- Собрать два RAID массива:
  - RAID 10 из дисков 0 и 1
  - RAID 10 из дисков 2 и 3
- В Boot Volume выбрать **Direct Attached Storage**
- Выбрать в качестве загрузочного первый логический диск


**Создание RAID 1 массивов (через hpssacli после установки ОС):**
```bash
# Установка утилиты (если недоступна в репозитории)
sudo apt update
sudo apt install -y hpssacli

# Просмотр дисков
sudo hpssacli ctrl all show config

# Создание RAID 1 (пример для контроллера, замените на ваш)
sudo hpssacli ctrl slot=0 create type=ld drives=1I:1,1I:2 raid=1
sudo hpssacli ctrl slot=0 create type=ld drives=1I:3,1I:4 raid=1

# Проверка результата
sudo hpssacli ctrl slot=0 ld all show
```

**Итоговая конфигурация:**
- `/dev/sda` и `/dev/sdb` — первый RAID 1 массив (2TB полезного пространства)
- `/dev/sdc` и `/dev/sdd` — второй RAID 1 массив (2TB полезного пространства)

### 1.2 Установка параметров USB

**Вход в BIOS - F10:**
- Установить USB‑настройки
  - USB Functions	- Enabled
  - Legacy USB Support - Enabled
  - USB 2.0 Controller - Enabled
  - USB 2.0 Controller Mode - HiSpeed
  - BIOS EHCI Hand-Off - Enabled
  - Hot Plug USB FDD Support - Disabled
  - USB Mass Storage Device Configuration → Emulation Type - Hard Drive

### 1.3 Подготовка загрузочного диска

- Скачать образ ОС
- Проверить хэш образа
- На Windows (Rufus) установить
  - Схема раздела: MBR (для BIOS) или GPT (для UEFI)
  - Целевая система: BIOS или UEFI (без CSM)
  - Режим записи: ISO Image (не DD!)
  - Проверить на плохие блоки
- Установить на флешку (желательно USB2, размер не более 32GB)


### 1.4. Установка Ubuntu 24.04 LTS

**Использована автоматическа разметка загрузочного диска при установке:**

| Диск | Раздел | Точка монтирования | Размер | Файловая система |
|------|--------|-------------------|--------|------------------|
| /dev/sda | /dev/sda1 | / | 2TB    | ext4 |
| /dev/sdb | | Используется как зеркало /dev/sda (RAID 1) |        | |
| /dev/sdc | /dev/sdc1 | /mnt/data | 2TB    | ext4 |
| /dev/sdd | | Используется как зеркало /dev/sdc (RAID 1) |        | |

**Вручную:**

| Диск | Раздел | Точка монтирования | Размер | Файловая система |
|------|--------|-------------------|--------|------------------|
| /dev/sda | /dev/sda1 | /boot | 1GB | ext4 |
| | /dev/sda2 | / | 100GB | ext4 |
| | /dev/sda3 | swap | **НЕ ИСПОЛЬЗОВАТЬ (swap отключен для K8s)** | - |
| | /dev/sda4 | /var/lib/docker | остаток | ext4 |
| /dev/sdb | | Используется как зеркало /dev/sda (RAID 1) | | |
| /dev/sdc | /dev/sdc1 | /mnt/data | 2TB | ext4 |
| /dev/sdd | | Используется как зеркало /dev/sdc (RAID 1) | | |

**Важно:** При установке Ubuntu **НЕ создавайте swap раздел**. Kubernetes требует отключенного swap.

**После установки ОС:**

```bash
# Обновление системы
sudo apt update && sudo apt upgrade -y

# Установка необходимых пакетов
sudo apt install -y \
    curl wget git vim htop \
    apt-transport-https ca-certificates gnupg lsb-release \
    jq yq net-tools bridge-utils \
    nfs-common cifs-utils

# Отключение swap (дополнительная проверка)
sudo swapoff -a
# Удаление swap из /etc/fstab
sudo sed -i '/swap/d' /etc/fstab

# Настройка параметров ядра для HDD (без swap)
cat << EOF | sudo tee /etc/sysctl.d/99-k8s.conf
vm.swappiness=0
vm.vfs_cache_pressure=50
net.ipv4.ip_forward=1
net.bridge.bridge-nf-call-iptables=1
fs.inotify.max_user_watches=524288
fs.inotify.max_user_instances=512
EOF

sudo sysctl --system

# Настройка монтирования /mnt/data
sudo mkdir -p /mnt/data
sudo mount /dev/sdc1 /mnt/data

# Добавление в fstab для автоматического монтирования
echo "/dev/sdc1 /mnt/data ext4 defaults,noatime 0 2" | sudo tee -a /etc/fstab

# Создание директорий для хранения данных
sudo mkdir -p /mnt/data/k8s-storage/{postgres,elasticsearch,kafka,minio,chroma,harbor,monitoring}
sudo chmod 755 /mnt/data/k8s-storage
```

## 2. Установка базового ПО

### 2.1. Установка Docker

```bash
# Удаление старых версий
sudo apt remove -y docker docker-engine docker.io containerd runc

# Установка через официальный репозиторий
sudo mkdir -p /etc/apt/keyrings
curl -fsSL https://download.docker.com/linux/ubuntu/gpg | sudo gpg --dearmor -o /etc/apt/keyrings/docker.gpg

echo "deb [arch=$(dpkg --print-architecture) signed-by=/etc/apt/keyrings/docker.gpg] https://download.docker.com/linux/ubuntu $(lsb_release -cs) stable" | sudo tee /etc/apt/sources.list.d/docker.list

sudo apt update
sudo apt install -y docker-ce docker-ce-cli containerd.io docker-buildx-plugin docker-compose-plugin

# Настройка Docker для kind (использование systemd cgroup)
sudo mkdir -p /etc/docker
sudo cat << 'EOF' | sudo tee /etc/docker/daemon.json
{
  "exec-opts": ["native.cgroupdriver=systemd"],
  "log-driver": "json-file",
  "log-opts": {
    "max-size": "100m",
    "max-file": "3"
  },
  "storage-driver": "overlay2",
  "data-root": "/var/lib/docker"
}
EOF

# Перезапуск Docker
sudo systemctl restart docker
sudo systemctl enable docker

# Добавление текущего пользователя в группу docker
sudo usermod -aG docker $USER
newgrp docker
```

## 3. Создание и настройка kind-кластера

### 3.1. Создание конфигурационного файла kind

extraMounts hostPath - путь в хостовой ОС, containerPath - путь в kind node (Docker container). Отображение volume для пода описывается в манифесте пода в volumeMounts. 

```bash
cat << 'EOF' > kind-config.yaml
kind: Cluster
apiVersion: kind.x-k8s.io/v1alpha4
name: rag-test
nodes:
- role: control-plane
  extraPortMappings:
  - containerPort: 80
    hostPort: 80
    protocol: TCP
  - containerPort: 443
    hostPort: 443
    protocol: TCP
  - containerPort: 8080
    hostPort: 8080
    protocol: TCP
  extraMounts:
  - hostPath: /mnt/data/k8s-storage
    containerPath: /mnt/data
- role: worker
  extraMounts:
  - hostPath: /mnt/data/k8s-storage
    containerPath: /mnt/data
- role: worker
  extraMounts:
  - hostPath: /mnt/data/k8s-storage
    containerPath: /mnt/data
networking:
  podSubnet: "10.244.0.0/16"
  serviceSubnet: "10.96.0.0/12"
kubeadmConfigPatches:
- |
  apiVersion: kubelet.config.k8s.io/v1beta1
  kind: KubeletConfiguration
  evictionHard:
    nodefs.available: "5%"
    nodefs.inodesFree: "5%"
    imagefs.available: "5%"
    memory.available: "1Gi"
  evictionSoft:
    nodefs.available: "10%"
    nodefs.inodesFree: "10%"
    memory.available: "2Gi"
  evictionSoftGracePeriod:
    nodefs.available: "2m"
    nodefs.inodesFree: "2m"
    memory.available: "2m"
EOF
```

## 4. Установка Istio Service Mesh

### 4.1. Установка Istio с профилем sidecar

Для HP DL160 G6 используем **sidecar profile** (а не ambient) — он дает полную функциональность согласно архитектуре:
- Circuit Breaker (L7)
- Retry с таймаутами
- Traffic Splitting для A/B тестирования
- Полная observability (Kiali).

```bash
# Установка Istio с default profile (sidecar) для полной функциональности
istioctl install --set profile=default -y

# Проверка
kubectl get pods -n istio-system
```

### 10.3. Инициализация OpenTelemetry в коде (пример для Flask)

```python
# services/rag-converter/src/main.py
from opentelemetry import trace
from opentelemetry.instrumentation.flask import FlaskInstrumentor
from opentelemetry.instrumentation.requests import RequestsInstrumentor
from opentelemetry.instrumentation.sqlalchemy import SQLAlchemyInstrumentor

def init_telemetry(app, db_engine):
    # Инструментация Flask
    FlaskInstrumentor().instrument_app(app)
    
    # Инструментация HTTP запросов
    RequestsInstrumentor().instrument()
    
    # Инструментация БД
    SQLAlchemyInstrumentor().instrument(engine=db_engine)
    
    # Получение tracer
    tracer = trace.get_tracer(__name__)
    return tracer
```

## Приложение B: Скрипты для автоматизации

### B.1. Скрипт проверки готовности всех сервисов

```bash
#!/bin/bash
# check-all-services.sh

NAMESPACES="data-infra observability security registry ingress data-plane compute-plane control-plane api-plane experiment-plane batch-plane"

echo "Waiting for all services to be ready..."

while true; do
  TOTAL=0
  READY=0
  for ns in $NAMESPACES; do
    NS_TOTAL=$(kubectl get pods -n $ns -o json | jq '.items | length')
    NS_READY=$(kubectl get pods -n $ns -o json | jq '[.items[] | select(.status.phase == "Running")] | length')
    TOTAL=$((TOTAL + NS_TOTAL))
    READY=$((READY + NS_READY))
  done
  
  echo "Ready: $READY / $TOTAL"
  
  if [ "$READY" -eq "$TOTAL" ] && [ "$TOTAL" -gt 0 ]; then
    echo "All services are ready!"
    break
  fi
  
  sleep 5
done
```
