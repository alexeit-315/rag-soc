## Новый раздел 7: Автоматизация тестирования в CI/CD

### 7.1 Матрица тестов в pipeline (обновлено)

| Тип тестов | Инструмент | Стадия | Покрытие | Порог блокировки |
|------------|------------|--------|----------|------------------|
| **Unit-тесты** | pytest | `unit-test` | ≥ 50% бизнес-логики | ❌ Coverage < 50% |
| **Integration-тесты** | pytest + testcontainers | `integration-test` | Критические пути (БД, Kafka, Redis) | ❌ Провал тестов |
| **DAST** | OWASP ZAP | `dast` | OWASP Top 10 | ❌ High/Critical находки |
| **E2E Functional** | pytest + requests | `e2e-test` | Основные сценарии (чат, SOC, поиск) | ❌ Провал тестов |
| **E2E Quality (RAGAS)** | pytest + ragas | `quality-test` | Faithfulness, answer correctness, context precision | ❌ Faithfulness < 0.8, Correctness < 0.75 |
| **Smoke tests (prod)** | pytest + requests | В рамках `deploy-prod` | Критичные эндпоинты (/health, /ready, /api/v1/chat) | 🔄 Auto-rollback при провале |

### 7.2 E2E Quality тестирование (RAGAS)

**Метрики:**
| Метрика | Описание | Порог (prod) | Порог (staging warning) |
|---------|----------|--------------|-------------------------|
| `faithfulness` | Следует ли ответ из контекста | ≥ 0.8 | ≥ 0.75 |
| `answer_correctness` | Правильность ответа (сравнение с golden) | ≥ 0.75 | ≥ 0.70 |
| `context_precision` | Релевантность контекста запросу | ≥ 0.7 | ≥ 0.65 |
| `recall@k` | Полнота найденных релевантных чанков | ≥ 0.8 | ≥ 0.75 |
| `no_answer_rate` | Процент отказов (no-answer) | ≤ 10% (strict), ≤ 5% (balanced) | — |

**Тестовый набор (Golden Dataset):**
- **Объём:** 100+ QA-пар (вопрос → ожидаемый ответ + источники).
- **Формат:** JSONL в `tests/e2e/quality/datasets/golden_v1.jsonl`.
- **Хранение:** Object Storage (S3) с версионированием.
- **Обновление:** Ежеквартально ML-инженерами.

**Запуск:**
```bash
pytest tests/e2e/quality/ \
  --env=staging \
  --ragas-metrics=faithfulness,answer_correctness,context_precision \
  --dataset=tests/e2e/quality/datasets/golden_v1.jsonl \
  --junitxml=e2e-quality-report.xml
```

### 7.3 Интеграционные тесты (testcontainers)

**Конфигурация:**
- PostgreSQL (testcontainers: `postgres:15-alpine`).
- Redis (`redis:7-alpine`).
- Qdrant (`qdrant/qdrant:latest`).
- Kafka (`confluentinc/cp-kafka:latest`).
- Elasticsearch (`elasticsearch:8.11.0`).

**Пример (`docker-compose.test.yml`):**
```yaml
version: '3.8'
services:
  postgres:
    image: postgres:15-alpine
    environment:
      POSTGRES_DB: test_db
      POSTGRES_USER: test_user
      POSTGRES_PASSWORD: test_pass
    ports:
      - "5432:5432"
  
  redis:
    image: redis:7-alpine
    ports:
      - "6379:6379"
  
  qdrant:
    image: qdrant/qdrant:latest
    ports:
      - "6333:6333"
```

**Запуск в CI:**
```yaml
test:integration:
  services:
    - docker:24-dind
    - postgres:15-alpine
    - redis:7-alpine
    - qdrant/qdrant:latest
  script:
    - pytest services/*/tests/integration/ --junitxml=integration-report.xml
```

### 7.4 Нагрузочное тестирование (Nightly)

**Инструмент:** k6

**Сценарий (`tests/load/chat_scenario.js`):**
```javascript
import http from 'k6/http';
import { check, sleep } from 'k6';

export const options = {
  stages: [
    { duration: '5m', target: 10 },  // 10 RPS
    { duration: '10m', target: 50 }, // 50 RPS (пик)
    { duration: '5m', target: 0 },   // Спад
  ],
  thresholds: {
    http_req_duration: ['p(95)<45000'], // p95 < 45 сек
    http_req_failed: ['rate<0.01'],     // error rate < 1%
  },
};

export default function () {
  const payload = JSON.stringify({ query: 'Как настроить RAID?', mode: 'balanced' });
  const res = http.post('https://staging.rag-soc.internal/api/v1/chat', payload, {
    headers: { 'Content-Type': 'application/json' },
  });
  check(res, { 'status is 200': (r) => r.status === 200 });
  sleep(1);
}
```

**Запуск:** Nightly в 02:00 MSK (отдельный pipeline `load-tests.yml`).

### 7.5 Flaky tests мониторинг

**Определение:** Тест, который проходит/проваливается без изменений кода.

**Метрика:** `flaky_tests_count` (за неделю).

**Действия:**
- > 3 flaky tests за неделю → алерт в Slack.
- > 10 flaky tests за неделю → блокировка мержа до исправления.

**Инструмент:** pytest-flake-finder + кастомный скрипт анализа JUnit-отчётов.
